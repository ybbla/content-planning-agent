# 04 AI 辅助、人工决策与验证

## 协作方式

本项目由人和 AI 协作完成：人工负责目标取舍、技术资源、验收方向和功能优先级，AI 负责方案细化、代码与测试实现、真实模型运行、证据检查和文档整理。以下记录仅包含实际发生的贡献，不把 AI 生成内容虚构为人工手工修改。

## AI 辅助内容

本次使用 Claude Code 协助：

- 分析题目与交付规范，通过多轮问题形成设计树和实施计划。
- 使用 Python 原生实现 ReAct 循环、四个业务工具、状态持久化与 CLI，未使用现成 Agent 框架。
- 编写 pytest、异常与篡改负例，生成 Mock 和真实模型运行产物。
- 接入 OpenAI 兼容 Responses API，补充真实响应元数据和证据校验。
- 实现失败步骤续跑、检查点恢复和跨进程测试。
- 进行多轮独立代码审查，修复发现的问题并同步 README、五份文档和 examples。

## 人工决策与实际贡献

人工在项目中完成了以下真实工作：

1. **确定需求和设计取舍**：通过 28 个编号问题确认核心范围、Python 原生技术栈、真实模型与 Mock 边界、CLI、四工具闭环、最终方案计费、JSON 协议、显式失败恢复、任务幂等、12 步上限、费用数据和测试矩阵，并批准实施计划。
2. **审查计划与边界**：要求核对计划与题目约束，关注异常、重复执行、保存状态、证据真实性和任务完成差异，推动补充边界设计与验证。
3. **提供模型接入方式**：提供火山方舟 OpenAI 兼容 Responses API 的调用示例、接口地址和模型名，使项目能够执行真实模型验收。认证信息仅保存在本地 `.env`，未写入项目交付文件。
4. **确定增强方向**：在核心链路完成后，要求补全失败步骤续跑加分项，并要求先规划再执行、同步更新全部文档。
5. **确认协作产物**：对功能现状、真实 ReAct 证据和续跑结果进行阶段性审阅，决定后续完善方向。

## 验证与责任边界

AI 实际执行了 pytest、标准场景 CLI、重复执行、步数上限、real 缺配置、两次进程续跑和 examples 静态校验。首次测试出现一个 fixture 共享状态问题，修正测试隔离后通过。独立审查发现异常 abort 类型、提前无方案声明、永久故障、存储异常、输入枚举、损坏记录、检查点篡改和证据校验等问题；修复并增加负例后，最终 100 项测试通过。

真实模型方面，AI 使用人工提供的接入配置实际生成 `real_normal`、`real_over_budget`、`real_tool_failure` 和 `real_resume_failure_first/second`，未使用 Mock 或手工编辑动作冒充真实决策。随后逐条核对了 12→8 重规划、故障显式重试、历史步骤及 API 元数据恢复，`python -m src.validate_examples --require-real` 通过。

因此，本项目的人机协作事实是：**人工持续作出产品与验收决策并提供必要资源，AI 承担实现、测试、运行和文档工作；双方并未混同贡献归属。**
