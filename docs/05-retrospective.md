# 05 复盘

## 最难问题

最难的是让“模型自主决策”和“程序硬约束”同时成立。程序若自动换方案或自动重试，会削弱 ReAct 证据；若只做提示词约束，又可能超预算保存。最终分工是模型选择动作，工具校验依赖、最新估算、预算和时间，所有调整以模型动作进入 Trace。

第二个问题是终止状态一致性。方案保存后再出现模型错误或步数上限，不能返回与实际落盘相矛盾的未完成。实现以保存事实优先，并保留 after_save 诊断。

第三个问题是重复执行不只是“保存防重”。相同 task_id 携带不同输入时必须冲突，重复调用还应在模型创建前短路，避免无意义 API 消耗。

追加的失败续跑进一步区分了成功记录与未完成检查点：历史步骤和 API 元数据必须连续恢复，本次新增步数单独计预算；检查点校验和、嵌套状态、故障配置与模型模式都需验证，保存记录仍是完成事实的唯一权威。

## 学习收获

- 估算成功与方案可行是两个维度，必须分开建模。
- 最终方案报价与累计实际支出是不同口径；本题采用前者，不能将 12 和 8 相加。
- 失败测试要同时断言状态、副作用和之前成功结果，不能只看最终退出状态。
- Mock 很适合确定性验证流程，但真实模型决策必须由 real Trace 单独证明。
- 测试 fixture 的共享状态也可能造成假失败，需要检查测试隔离。
