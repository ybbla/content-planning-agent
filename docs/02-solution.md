# 02 方案与技术取舍

## 调用流程

```text
JSON 输入校验
  → task_id + 业务指纹幂等检查
  → 有未完成检查点时恢复运行态与历史观察
  → 模型输出一个 JSON 动作
  → 严格解析与参数校验
  → 白名单工具执行
  → 结构化观察反馈模型
  → 下一动作 / finish / abort / 上限
  → result.json + trace.json
```

真实模型与 Mock 共用 `Agent`、动作解析、业务工具和持久化代码。模型只选择动作；程序不自动换候选、不自动重试。工具负责不可绕过的依赖和预算约束。

## 模块

- `src/agent.py`：ReAct、计步、观察、终止与保存事实优先。
- `src/model.py`：OpenAI 兼容模型、确定性 Mock、协议测试 QueueModel。
- `src/tools.py`：四工具、报价、依赖、故障注入、原子保存。
- `src/state.py`：成功任务、未完成检查点存储和原子 JSON 写入。
- `src/schemas.py`：输入校验和业务指纹。
- `src/main.py`：CLI 与文件产物。
- `src/validate_examples.py`：提交证据静态校验。

## 决策协议

每轮只接受 `action`、`arguments`、`rationale` 三个字段。Markdown 围栏、解释文字、非法 JSON 和未知动作均拒绝，作为观察反馈并计一步。Trace 只保留简短依据，不保存完整提示词或内部推理。

正常保存后由模型 `finish`。如果保存后发生模型错误、abort 或步数上限，以已经落盘的事实返回 completed 并添加诊断，避免状态与保存结果矛盾。

## 重规划与失败

估算超预算属于成功估算、`feasible=false`，不是工具故障。模型可复用同一脚本估算另一素材，再用匹配的最新估算保存。旧估算不能保存不同候选。只有全部候选均有估算且没有任何可行报价时，才接受 `no_feasible_plan`；提前终止该原因会收到 `PREMATURE_NO_FEASIBLE` 观察。缺口绑定到一个明确的最低成本候选，并另列每个候选的缺口，避免组合不同方案的费用与耗时。

故障在业务函数和副作用之前注入。临时错误只失败一次，允许模型显式重试；永久错误在每次匹配调用时都失败，模型应换路或停止。失败不创建脚本、估算或保存记录，已有成功结果不清空。

## 失败续跑

未完成检查点与成功任务记录分开存放在 `state-dir/checkpoints/` 和 `tasks/`。每次模型动作后原子保存候选、脚本、估算、最新估算、累计步骤、API 元数据、最后观察、故障配置及注入状态，并写入整体校验和；即使协议错误或模型不可用，也可在相同模式下恢复。恢复前验证 ID 连续性、估算依赖、最新估算、最后观察和逐步响应元数据；无成功记录时，检查点中的保存方案无效。

续跑要求相同 `task_id` 和业务指纹，并沿用 real/mock 模式与真实模型配置，避免跨模式混合证据。恢复后 `step_count` 保留累计历史，`new_step_count` 只计算本次动作，`--max-steps` 限制每次调用的新增动作。`resumed_from_run_id` 指向上一次运行，结果与 Trace 同时保留历史前缀。

完成保存后清理检查点，后续相同任务仍按成功幂等短路。检查点损坏、指纹冲突或模式冲突不会覆盖原记录。存储失败会返回明确 `storage_error`；若方案已保存，完成事实优先并保留清理/写入诊断。

## 幂等

成功记录保存 `task_id`、业务输入指纹、方案校验和、方案和原模型信息。重复执行在创建模型客户端前短路，写零动作的新 Trace。指纹包含主题、预算、截止时间和质量偏好，不包含故障配置和运行模式。同 ID 不同业务输入返回 `task_id_conflict`，不覆盖旧方案；空对象、非法 UTF-8、缺字段、嵌套结构错误或校验和不匹配均返回 `storage_error`。

## 技术取舍

采用 Python 原生循环而非 LangGraph 等框架：本项目只有一个循环和四个工具，原生实现可以直接展示协议、观察和状态转移，也减少依赖。`openai` 只负责兼容 API，`python-dotenv` 只读取本地配置，其余使用标准库。API 超时 30 秒、SDK `max_retries=0`，避免隐藏重试干扰步数与失败证据。

## 限制

只支持正常返回未完成后的顺序续跑，不支持两个进程同时恢复或保存的并发控制。工具执行与检查点写入不是事务，强杀窗口内可能需要重放非保存工具；方案保存通过成功记录优先去重。Mock 是测试替身，不能证明真实模型规划能力。
